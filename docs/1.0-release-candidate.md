# ModernORM 1.0.0-rc.1

The candidate pairs ModernORM and ModernORMBundle at `1.0.0-rc.1`. The tags and Packagist packages are publication gates. The installation command applies once both candidate versions are available.

```sh
composer require andreybolonin/modernorm:1.0.0-rc.1 andreybolonin/modernorm-bundle:1.0.0-rc.1 --with-all-dependencies
```

## Public API for 1.0

The documented ORM configuration, mapping attributes, EntityManager and repository operations, SQL query API, bulk writes, cache facade, Statistics API and supported Symfony integration form the public contract. Consult the compatibility matrix for supported combinations. Metadata serialization, persisters, hydrators and UnitOfWork internals are internal implementation details. [Compatibility matrix](compatibility.md) · [Mapping scope](mapping-scope.md)

The migration contract covers additive schema changes, catalog-based diff and the documented rollback paths. Changes to declarative predicates, exclusion constraints, or STORED expressions can require a hand-written migration. Migrations that change a managed trigger function require an explicit rollback migration. [Schema attributes](mapping-scope.md#postgresql-check-constraints)

## Upgrade from beta

1. Review the [core changelog](../CHANGELOG.md) and existing mapping changes before deploying.
2. Invalidate or version metadata and query-plan caches. The candidate uses metadata cache format V18. Restart workers and coordinate any shared entity L2 cache namespace change with the rollout.
3. Generate a schema diff against a copy of the existing PostgreSQL database. Review the migration and provision required extensions or externally managed trigger functions. Apply it and verify an empty repeat diff.
4. Run application smoke tests for persisted entities and configured cache adapters before rolling out.

## Local verification

PHP 8.5.13 and PostgreSQL 18.7 passed the following checks for the working-tree candidate.

- Composer validated both manifests. Both local dist archives included the license and matched all 339 core and 68 Bundle PHP source files.
- A clean Composer consumer installed both RCs from the local dist archives and applied a migration to an empty schema. The repeated diff was empty, and PostgreSQL enforced the declared CHECK.
- A second consumer installed the published core `0.1.0-beta.5` and Bundle `0.1.0-beta.6` from Packagist. It upgraded to the local RC archives with versioned cache namespaces, added a CHECK to its existing schema, preserved the stored entity and returned an empty repeat diff.
- The core release consumer passed CRUD, lazy batching, rollback recovery and optional L2 checks. The Bundle production Symfony smoke passed with only runtime dependencies installed.

## Release gates

- Run the full core and Bundle CI on the exact candidate revisions. Pin that core revision for the Bundle schema tests.
- Verify both Composer distributions in an isolated application. Once the RCs are published, repeat the clean install and beta-to-RC update with Packagist as the sole package source.
- Record migration and release evidence and review archive contents and licenses before tagging stable.
